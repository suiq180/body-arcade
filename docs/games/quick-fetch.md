# 번개 심부름 (`quick-fetch`)

> 하드웨어: 📷 카메라 (웹캠 사물 인식) | 원래 조작: 진행자가 말로 "○○ 가져와!" 하는 파티 놀이 | 플레이 시간: 한 판 약 3분 | 인원: 2~4인 (한 웹캠 앞에서 동시에)

## 1. 한 줄 소개
화면에 물건이 뜨면 **방 안에서 그 물건을 찾아 내 칸에 먼저 보여 준 사람이 승리**. 웹캠이 물건을 알아보고 누가 먼저였는지 자동으로 판정한다.

## 2. 원래 콘셉트에서 가져온 것 / 바꾼 것
- 가져온 것: "○○ 먼저 가져오기" 달리기 놀이, 라운드마다 1등 점수
- 바꾼 것:
  - 진행자 판정 → **웹캠 사물 인식(Teachable Machine 이미지 모델)으로 자동 판정**
  - 한 웹캠 화면을 인원수만큼 **세로 칸으로 나눠** 각자 자기 칸에 물건을 보여 준다

## 3. 물건 (사용자 지정 5종)
| 라벨(모델) | 화면 표시 |
|---|---|
| 스마트폰 | 📱 스마트폰 |
| 지갑 | 👛 지갑 |
| 라이터 | 🔥 라이터 |
| 에어팟 | 🎧 에어팟 |
| 마우스 | 🖱️ 마우스 |

- 인식 모델: `tm-my-image-model/` (Teachable Machine, 224×224, 라벨 5개) → 사이트에서는 `public/models/quick-fetch/`에 복사해 쓴다 (오프라인 동작).
- 모델에 **'아무것도 없음(배경)' 라벨이 없다** → 빈 화면도 5개 중 하나로 판단할 수 있으므로 아래 4장의 "출발 전 기준값" 규칙으로 보완한다.
- 실제 웹캠 확인 결과 (2026-11-03): 빈 상자가 **마우스**로 인식됨, **에어팟·마우스**는 보여 줘도 인식이 잘 안 됨.
  → 빈 상자가 이미 마우스로 높게 나오면 기준값 규칙 때문에 마우스 라운드는 확정이 안 된다. 코드로는 고칠 수 없어 **모델 재학습**으로 해결한다.
- 재학습 방법: Teachable Machine에 **`배경` 클래스를 추가**(빈 책상·사람만 서 있는 장면 등)하고, 에어팟·마우스 사진을 게임 상자 크기·거리로 더 찍는다. 내보낸 파일을 `tm-my-image-model/`과 `public/models/quick-fetch/`에 덮어쓴다.
- 재학습 모델 적용 (2026-11-03): `tm-my-image-model2/` (라벨 6개, `빈화면` 추가) → `public/models/quick-fetch/`에 교체. 단색·잡음 화면은 빈화면 99% 이상.
- 코드는 `ITEMS`에 없는 라벨(예: `배경`)을 자동으로 '빈 상자'로 처리한다: 문제로 안 나오고, "그건 ○○이에요" 안내도 없음.
- 준비 화면의 물건 목록 옆에 물건별 **지금 확률(칸 중 최대)**을 표시한다. 재학습 후 인식이 잘 되는지 바로 확인하는 데 쓴다.

### 빈 화면 보정 (2026-11-03 추가)
- 문제: Teachable Machine은 학습 때 웹캠 **가운데 정사각형만** 저장한다 → 화면 양 끝 칸(예: 3인 P3의 창문·주황 벽)은 모델이 처음 보는 장면이라 빈 칸을 물건(스마트폰 92%)으로 착각했다.
- 해결: 준비 화면에 **'빈 화면 기록'** 단계 (필수). 모두 비켜선 상태로 3초 뒤 2초 동안 칸별 모습(모델의 특징값 1280개)을 기록한다.
- 게임 중 칸이 기록한 빈 화면과 **코사인 유사도 0.9 이상**이면 모델 추측과 상관없이 '빈 상자'로 본다 (모든 물건 확률 0).
- 장소·조명·카메라가 바뀌면 다시 기록한다 (카메라를 바꾸면 기록이 자동으로 지워짐). 준비 화면에 칸별 유사도가 표시돼 기준값 조정에 쓴다.
- **자동 갱신**: 라운드 준비 시간에만, 유사도 0.93 이상(확실히 빈) 칸의 기록을 인식 1번마다 5%씩 지금 모습 쪽으로 옮긴다 → 조명이 서서히 바뀌어도 다시 기록할 필요가 없다. 물건을 찾는 중에는 기록을 건드리지 않는다.
  - 합성 영상 시험 (화면을 단계적으로 어둡게): 갱신 끔 → P3 0.894(빈 상자 기준 미달), 갱신 켬 → 0.944 유지. 갱신 중 물건을 넣어도 기록이 물건 쪽으로 끌려가지 않음(0.496).
- **플레이 기록**: 라운드마다 칸별 빈 화면 유사도(`emptySim.prepAvg` 준비 평균 / `goMin` 출발 뒤 최저 / `atConfirm` 1등 확정 순간)를 JSON에 남긴다 → 실제 플레이 기록으로 `emptySim` 기준값을 맞춘다.
- 합성 영상 시험: 빈 칸 1.00, 물건을 넣으면 0.51, 사람이 들어오면 0.46. 실제 웹캠의 잡음·자동 노출에서의 값은 사용자 확인 필요.

## 4. 규칙
- 인원 2·3·4명 중 선택. 카메라 화면을 왼쪽부터 P1, P2 … 칸으로 나눈다 (거울 화면 기준).
- 각 칸 가운데의 **정사각형 인식 상자**만 인식한다. 상자에 물건을 가까이 보여 줘야 한다.
- 한 판 = 5라운드. 5가지 물건이 한 번씩 무작위 순서로 나온다.
- 라운드 흐름
  1. **준비 (3초)**: "손에 든 물건을 내려놓고 자기 칸에 서세요" — 이 동안 칸마다 인식값을 모아 **기준값**으로 쓴다.
  2. **출발**: 목표 물건이 크게 뜨고 신호음. 모두 찾으러 달려간다.
  3. **판정**: 내 칸에서 목표 물건 확률이 0.85 이상이고 기준값보다 0.35 이상 높은 상태가 **0.6초 이어지면** 확정 → 가장 먼저 확정된 사람이 라운드 1등.
  4. 20초 안에 아무도 못 하면 라운드 무효.
  5. **결과 (2.5초)**: 1등과 걸린 시간 표시 후 다음 라운드.
- 다른 물건을 보여 주면 그 칸에 "그건 ○○이에요!" 표시만 하고 벌점은 없다.
- 같은 순간(같은 인식 주기)에 둘 이상 확정되면 모두 1등.

### 점수
- 라운드 1등: 100점 + 속도 보너스 (5초 안이면 최대 50점, 20초에 0점으로 줄어듦)
- 최종: 점수 합계. 결과 화면에 1등 횟수·평균 시간 표시

## 5. 화면
- 위: 라운드, 남은 시간, 플레이어별 점수
- 가운데: 거울 카메라 영상 + 칸 구분선 + 칸마다 인식 상자, 칸 아래에 **지금 인식 중인 물건과 확률 막대** (인식 상태 항상 표시, 기획서 8.4)
- 목표 물건은 화면 위쪽 가운데 큰 카드로 표시
- 확정되는 동안 상자 테두리가 차오르는 진행 표시

## 6. 입력 끊김
- 카메라 연결이 끊기면(영상 트랙 종료) 자동 일시정지 + 안내. 다시 연결되면 이어서 진행.

## 7. 완료 조건
- [ ] 2~4인 칸 나누기와 칸별 인식이 화면에 표시된다
- [ ] 5라운드가 끝까지 진행되고 결과 화면에 점수·1등 횟수가 나온다
- [ ] 기준값·확정 규칙으로 빈 칸이 저절로 1등이 되지 않는다 (사용자 확인 필요)
- [ ] 실제 웹캠으로 물건 5종 인식 (사용자 확인 필요)
- [ ] 게임을 나가면 카메라가 꺼진다
