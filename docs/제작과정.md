## 2. 작업 기록 (시간 순)

### 2026-10-29 — 전달받은 게임 2종 연결
- 카카오톡 받은 파일의 `eye-ball-game`, `ghost-convenience-3d`를 기존 게임 카드에 연결. 자체 준비·결과 화면을 유지하는 독립 문서(iframe)로 실행한다.
- `gaze-ball`: `public/games/gaze-ball/index.html`. 웹캠 보정, 방향키·스페이스 대체 입력, 게임패드 진동. 즉시 종료되던 점프 수정, 카메라 중복 시작 방지와 문서 종료 시 장치 정리 추가. 인식 모델 로딩은 인터넷 필요.
- `ghost-store`: `games/ghost-store/` 소스를 Vite 별도 HTML 진입점으로 빌드. Three.js 추가, 제공된 모델·텍스처는 `public/games/ghost-store/assets/`에 포함. 외부 에셋 출처는 `games/ghost-store/README.md`에 보존. 새 에셋 다운로드는 하지 않음.
- 기존 장치 분류는 유지하며 소개에 현재 체험판의 실제 조작 방식과 VR 미지원을 명시. 원본 게임 결과·재시작 화면을 사용하며 공통 최고 기록에는 연결하지 않음.
- 타입 검사·배포 빌드 통과. Chrome에서 허브 소개 → 시작 → iframe 게임 실행 확인: 공 게임 진행률 증가, 편의점 3D 렌더링·타이머 감소, 스크립트 오류 및 리소스 요청 실패 0건. 실제 웹캠 시선 정확도·게임패드 진동·조이스틱은 사용자 확인 필요.

## 3. 사이트 구조 한눈에 보기

```
주소(#)                 화면                         코드
#/device/<장치>         허브                         src/hub/hub.ts
#/setup/camera          카메라 장치 테스트           src/setup/camera-setup.ts
#/play/<게임>           ┬ 플레이 화면 있는 게임       src/games/play.ts → 게임 소개 → 장치 준비 → 게임 → 결과
                        └ 아직 없는 게임(전시 모드)    src/games/info.ts → 소개 페이지 + "점검 중"
```

| 위치 | 역할 |
|---|---|
| `src/main.ts` | 주소(#)에 따라 화면 고르기, 화면 떠날 때 정리(카메라 끄기 등) |
| `src/games/types.ts` | 모든 게임이 따르는 형식 — `GameMeta`(카드 정보), `GameModule`(게임 코드), `GameResult` |
| `src/games/registry.ts` | 각 게임 폴더의 `meta.ts`를 **자동으로 모음**, `SHOWCASE_MODE`, `POPULAR_RANKING` |
| `src/games/<게임>/` | `meta.ts`(카드·소개 정보) · `index.ts`(GameModule) · `config.ts`(밸런스 수치) · `rules.ts`(순수 규칙 로직) |
| `src/games/_template/` | 새 게임 견본 (20초 두 손 들기). 밑줄 폴더는 사이트에 등록 안 됨 |
| `src/games/play.ts` | 한 판의 흐름(소개→준비→게임→결과). 어떤 게임이든 공통. `SETUPS`에 장치 준비 화면 연결 |
| `src/input/` | 장치 어댑터. 게임은 장치 API를 직접 부르지 않음 |
| `src/setup/` | 장치 준비 화면 |
| `src/shared/` | 결과 화면, 디버그 패널(<kbd>`</kbd>), 효과음, 뼈대 그리기, 장치 지원 확인 |
| `docs/games/` | 게임별 기획서 (게임 만들기 전에 반드시 읽기) |

## 4. 새 게임 추가 절차 (체크리스트)

> body-rebel을 만들며 정리한 순서. 다음 게임부터 이 순서대로 진행하고, 바뀐 점은 여기에 고쳐 적는다.

**준비**
1. `docs/games/<게임ID>.md` 기획서가 있는지 확인 (없으면 먼저 요청 — CLAUDE.md 11장).
2. 이 문서의 "게임별 기록"과 "주의할 점"을 읽는다.
3. 기획서에 없는 판단이 필요하면 선택지를 만들어 먼저 묻는다. 사소한 건 정하고 보고.

**만들기**
4. **어댑터** — 필요한 장치 어댑터가 `src/input/`에 없으면 만든다. `start()`/`stop()`/이벤트, 정규화된 값(0~1 좌표 등). 판별 로직은 장치와 분리된 순수 파일로.
5. **장치 준비 화면** — `src/setup/`에 없으면 만든다 (권한 → 미리보기 → 입력 확인 → 시작 버튼, 원인별 오류 안내).
6. **config.ts** — 기획서의 밸런스 수치를 그대로 옮기고, 구현하며 추가한 값은 아래쪽에 "기획서에 없어서 추가"로 구분.
7. **rules.ts** — 문제 생성·정답 판정 같은 규칙은 화면과 분리된 순수 함수로 (무작위는 `rng` 주입 → 시험 가능).
8. **index.ts** — `GameModule`을 default로 내보낸다 (`setup`, `modes`, `start(container, input, { players, onFinish })` → `destroy()`). `src/games/_template/index.ts` 견본에서 시작. 게임 루프, 일시정지(입력 끊김), 피드백, 플레이 기록(log) 수집. 디버그 패널 연결.
9. **연결** — 게임 폴더의 `meta.ts`에서 `status: 'ready'` + `load: () => import('./index')`. 공용 파일은 손대지 않는다. (새 장치일 때만 `types.ts`의 `SetupInputs`와 `play.ts`의 `SETUPS`에 연결)
10. **결과 화면** — `renderResults`로 점수·최고 기록·다시 하기·기록 내보내기.

**검증** (실제 장치 없이 할 수 있는 것부터)
11. `npx tsc` 타입 검사.
12. 규칙 로직: 개발 서버 페이지에서 `await import('/src/games/<게임>/rules.ts')`로 무작위 시드 수백 번 돌려 검사.
13. 한 판 전체: 가짜 어댑터(합성 좌표·이벤트)로 끝까지 모의 플레이 → 점수·기록·일시정지·아이템 확인.
14. 화면: 데스크톱·좁은 화면·모바일에서 깨짐·가로 스크롤 확인.
15. `npm run build` 성공 확인.
16. 실제 장치 확인 항목은 "사용자 확인 필요"로 따로 보고.

**마무리**
17. `CLAUDE.md` 10장 체크, 이 문서의 "현재 상태" 표와 "작업 기록"·"게임별 기록" 갱신.
18. `npm run build` → `dist/`를 Netlify Deploys에 끌어다 놓기.

## 5. 주의할 점 (겪은 문제와 해결)

| 문제 | 원인 | 해결 |
|---|---|---|
| 개발 서버가 갑자기 꺼짐 (EBUSY) | 큰 파일을 폴더에 복사하는 중에 Vite가 감시하다 잠긴 파일을 만남 | `vite.config.ts`에서 `src`·`public`·`index.html`만 감시 |
| 화면 스타일이 통째로 사라짐 | 스타일 파일을 다시 쓰는 순간(빈 파일)을 개발 서버가 기억 | 파일 저장 후 새로고침, 그래도 안 되면 파일을 한 번 더 저장 |
| 카메라 영상이 까맣게 나옴 | 화면 밖 영상을 캔버스에 복사하는 방식이 일부 환경에서 검게 그려짐 | `<video>`를 화면에 직접 표시, 뼈대만 캔버스에. 검은 화면 감지 안내 |
| 화면 위 색 버튼이 잘림 | 4:3 영상을 16:9 칸에 꽉 채우며 위아래를 자름 | 영상 전체 표시(contain), 칸을 영상 비율에 맞춤 |
| 앱 미리보기에서 카메라가 안 됨 | 앱 안 브라우저는 카메라·마이크 차단 | 실제 확인은 크롬·엣지에서 |
| 점프가 인식 안 될 수 있음 | 공중에 있는 시간이 0.3초 유지 확정보다 짧음 | 점프만 확정 시간 0.12초 (`jumpConfirmMs`) |
| 모의 테스트에서 게임이 멈춤 | 숨겨진 탭에서는 `requestAnimationFrame`이 멈춤 | 테스트할 때만 타이머로 대신 돌림 (실제 플레이엔 문제없음) |
| 테스트에서 바꾼 config 값이 안 먹음 | 파일 수정 후 Vite가 다른 주소(`?t=`)로 모듈을 다시 불러 별개의 객체가 됨 | 테스트 전 페이지 새로고침 |
| 한글 폴더 경로 오류 (Node 스크립트) | 파일 주소가 `%ED%99...`로 인코딩됨 | `fileURLToPath` 사용 |
| 원작 이름 노출 위험 | 상표 규칙 (CLAUDE.md 2장) | 화면·코드에 원작 이름 금지, 기획서 참고 표에만 |
| 새 게임 카드가 허브에 안 보임 | `meta.ts`의 `id`가 폴더 이름과 다르거나, 폴더가 `_`로 시작 | 콘솔 경고 확인, 폴더 이름 = id |
